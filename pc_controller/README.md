# PC Controller（Windows PC側）

Windowsの操作画面からSSH経由でPi上のROS 2へ指令を送るテストプログラムです。**「ドライラン（GPIO出力なし）」はアプリ起動時に必ずチェックありです。実機出力する場合は、接続前にチェックを外してください。** 接続中は変更できません。切断後に切り替えて再接続してください。GUIはconnection.jsonのdry_run値よりチェックボックスを優先します。WindowsへのROSインストールは不要です。画像表示にはPillowを使います（このPCのCodex同梱Pythonには導入済み）。

## 起動

PowerShellで次を実行します。

```powershell
cd C:\_Project\_RaspPi4_ROS\ros2-rove-one\pc_controller
.\start.ps1
```

Codex同梱Pythonがあれば自動使用します。別環境ではTkinter付きのPython 3.10以上とOpenSSHクライアントが必要です。スクリプト実行ポリシーで起動できない場合は、Pythonで`controller.py`を直接起動できます。

1. Piを起動し、有線接続する。
2. ドライランのチェック状態を選び、「SSH接続」を押し、接続済みの表示を待つ。
3. 方向ボタンを離した状態で「有効化」を押す。
4. 前進・後退・旋回ボタンを押し続けると指令を送信する。離すと速度0。
   ↑↓←→キーも前進・後退・左旋回・右旋回に対応し、離すと速度0。
   「一輪ずつ回す」の左前・左後・右前・右後にも正転・逆転ボタンがあり、押している間だけ指定の一輪へ指令を送る。離すと4輪とも速度0。
5. 「停止/無効化」またはSpaceで無効化。Esc/緊急停止でラッチ停止。
6. 緊急停止後は「有効化」1回で解除・走行可能。「ラッチ解除」だけでは無効状態を維持する。
7. 終了時は「切断」またはウィンドウを閉じる。

フォーカスを別アプリへ移すと無効化します。速度の数値は目標値で、実測速度ではありません。

## カメラ画像・水平線の調整

Piで[カメラノード](../ros2_ws/src/pi4_camera_vision/README.md)をhttp_preview:=trueで起動しておく。
PCアプリ右側の「映像接続」で映像のみ接続できる。「SSH接続」でも映像接続を開始する。
カメラ配信用のSSHトンネルは自動で空きローカルポートを選び、既存ブラウザー用トンネルと競合しない。

- 画像の**中央の赤い水平線**に、実際の水平線が合うようカメラの取り付けを手動で調整する。
- 地面は平坦・水平と仮定し、赤線より下半分だけを探索する。
- オレンジ枠は明部候補、緑の印は確定した目標。座標と左/中央/右の旋回目安を表示する。
- 目標や距離を使った自動走行は未接続。映像接続だけではモーター用SSHを起動しない。
- 画像受信とJPEG復号はバックグラウンドで行う。映像停止やアプリ切断で画像・目標表示をクリアする。
- Piのノードが未起動の場合は映像欄に接続エラーを表示する。PCからPiノードの自動起動はしない。

別のPythonを使う場合は、Tkinterに加えて`python -m pip install -r requirements.txt`が必要。
`python controller.py --camera`で、モーター未接続のまま映像接続を開始できる。
実映像と中央線の試験は`python camera_gui_test.py`。既存のgui_test.pyはドライランで実施する。

### 前輪による旋回

旋回は前輪のみで行い、後輪は前後進のDutyを維持します。停止中の旋回では後輪は出力0、前輪は速度欄による前後進時と同じDutyで左右逆転します。↑または↓と、←または→の同時押しに対応します。一方を離すと残ったキーの操作を続けます。↑↓同時・←→同時を含む組み合わせは出力0です。

走行中は、走行Dutyを基準として前輪のみ30%補正します。右旋回では左前輪130%・右前輪70%、左旋回では左前輪70%・右前輪130%とし、後輪は両輪とも走行Dutyを維持します。130%・70%は走行Dutyに対する倍率です。各輪は最大Dutyで個別に頭打ちとし、他輪は比例縮小しません。後退時も左右の倍率は同じで、走行Dutyの負符号を維持します。

実機設定・速度0.1では、前進は全輪20%、停止中の左旋回は左前−20%・右前20%・後輪0%、前進＋左旋回は左前14%・右前26%・後輪各20%です。詳細は[走行・前輪旋回仕様](../docs/ROS2パッケージ・Node仕様.md#421-pc-controllerの走行前輪旋回仕様2026-11-02改訂)を参照してください。

この操作にはPi側のcontrol.py・node.py・scripts/pc_bridge.pyも更新し、ROSパッケージを再ビルドする必要があります。従来のcmd_velによる差動制御は維持し、PC画面からは専用のsteer指令を使用します。

## 接続設定

`connection.json`で接続先・既存SSH鍵・known_hosts・Pi上のワークスペースを設定します。鍵パスはこのJSONからの相対パスです。秘密鍵は既存のものを参照し、コピー・表示しません。パスワードは保存せず、鍵認証だけを使用します。ホスト鍵が不一致の場合は接続を拒否します。

`log_directory`もJSONからの相対パスで指定し、現在は管理対象の外側にある`../../work_data/pc_controller/logs`へ記録します。省略時はプログラムと同じ場所の`logs/`を使用します。

Pi上には`pi4_motor_control`がビルド済みで、`~/ros2-rove-one/ros2_ws/src/pi4_motor_control/scripts/pc_bridge.py`が必要です。接続時に自動でブリッジと専用のモーター制御ノードを起動し、切断時に終了します。

## 構成と停止動作

```text
Windows Tk画面
  → OpenSSH stdinのJSON指令（100 msごと）
  → Pi pc_bridge.py（rclpy、GPIOなし）
  → cmd_vel / enable / emergency_stop
  → pi4_motor_control（接続時に選択したdry_run設定）
  → status JSON
  → SSH stdout → Windows画面・管理対象外のログ保存先
```

- ROS_DOMAIN_IDは既定88。さらに接続ごとに固有namespaceを作り、通常の`/cmd_vel`や別セッションから分離する。
- 実機モードはPi側の `config/motors-hardware-test.yaml` を使用し、PWM上限80%、起動時無効。PC画面の「有効化」後、方向ボタンを押すと出力する。車輪を浮かせて試験する。
- PCの指令ハートビートが350 ms途絶えるとブリッジが速度0・無効化する。
- ブリッジ自体が停止した場合も、モーター制御ノードの500 ms watchdogで無効化する。
- GUIの停止・フォーカス喪失・接続途絶時に指令保持を解除する。復帰後の再走行には有効化が必要。
- これはSSHと一般OS上のソフトウェア検証で、停止時間の実時間保証や実機の電気的安全性を確認するものではない。

## 自動試験

```powershell
$py = "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
& $py .\controller.py --gui-check
& $py .\smoke_test.py
# 上記に加えGUI操作経路・停止・切断も確認し、結果を設定済みログ保存先へ保存
.\validate.ps1
```

PC→SSH→ROS→仮想モーター→PCの往復で、前進/後退/旋回、ボタン解放相当の0指令、緊急停止、ラッチ解除、指令途絶、再有効化、切断、再接続を検証します。自動試験は設定にかかわらずdry-runを明示し、GPIOにアクセスしません。
