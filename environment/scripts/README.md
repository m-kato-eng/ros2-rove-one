# 環境の採取・再構築手順

## SSHによる実機採取（実行確認済み）

Windows側でcollect_remote.pyを実行する。接続先はPC操作プログラムのconnection.jsonを参照し、秘密鍵の内容は表示せず既存SSH認証を使用する。probe_linux.pyをSSH標準入力から実行し、結果はプロジェクト直下のwork_data/environmentへ保存する。実機へのスクリプト配置や設定変更は行わない。

```powershell
python managed/environment/scripts/collect_remote.py
```

2026-11-01に実行し、追加のXセッション定義も合わせて設定原本102件を採取した。初回の失敗・再試行は[採取結果](../manifests/current-2026-11-01.md)を参照。採取した原本をGit管理へ取り込む前に、秘密情報の有無を確認する。

## 簡易Bash版（未実行）

collect_readonly.shは作成済みだがPiで未実行。Windows側でBashの構文検査を試みたところ、実行環境の権限制限でBash本体が起動できなかった。LF改行のみ確認済み。

Pi上で次の読み取り用スクリプトを実行し、標準出力を管理対象外のファイルへ保存する。OS設定・パッケージ・GPIOを変更する処理、sudo、秘密鍵の読取は含めていない。保存前に同名ファイルがないことを確認する。

出力にはソフト・サービス等の環境情報が含まれるため、Gitへ取り込む前に内容を確認する。認証情報を含み得るAPT配布元ファイルやネットワーク設定を丸ごと採取する処理は含めていない。

## 再構築の順序

これは保存記録に基づく手順書。**全工程を再実行した再現性検証は未実施。** 自動構築・設定適用スクリプトは、未確認の初期構築情報を埋めてから作成する。

1. 予備SDへ、機種に適合するUbuntu 22.04 arm64のOSを準備する。元イメージの固有名は未確認なので、まず公式イメージの版・URL・ハッシュを確定する。
2. SSH、Python、必要ならXFCEと開発接続を準備する。過去の初期導入コマンドは完全には残っていないため、原本確認または新規構築検証が必要。
3. Universe、curl、ロケールを準備し、公式のros2-apt-sourceでROS配布元を登録する。記録された設定パッケージの版は1.3.0~jammy。
4. ros-humble-ros-base、ros-dev-tools、ros-humble-demo-nodes-cpp、ros-humble-demo-nodes-pyを導入する。過去の依存ソフトの版はmanifestsのTSVで照合する。配布元にその版が残っているとは限らない。
5. ~/.bashrcへROS環境読み込みを追加し、rosdepを初期化・更新する。
6. リポジトリ内のros2_ws/srcをPiの~/ros2_ws/srcへ配置し、ビルドする。
7. 元のデモ通信と、独自パッケージの単体・統合テストを実行する。GPIOは使わずdry-runを維持する。
8. OS・パッケージ・設定を再採取し、差分・試験結果・適用コミットを記録する。

ROS導入の元の実行コマンドは[ROS導入記録](../../../前回の作業ログ/2026-10-28_ROS2導入作業.md)、独自コードのビルド・試験手順は[パッケージ説明](../../ros2_ws/src/pi4_motor_control/README.md)を参照。

## 既存のSDイメージから戻す場合

別のSDカードへイメージを復元して起動し、Linux構成の採取とROS試験を実施する。元の動作カードを上書きする試験は避ける。圧縮・展開のハッシュ一致と、復元した環境が動作することは別々に確認する。
