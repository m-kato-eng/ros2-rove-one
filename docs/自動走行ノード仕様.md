# 自動走行ノード

`pi4_motor_control` パッケージに `autonomous_driving` を追加。
`object_recognition` は目標座標の検出に専念し、左右方向の算出は自動走行側で行う。

2026-11-10：既定の認識を[床の赤色レーザー光点](床の赤色レーザー光点・検出追跡仕様.md)へ切り替えた。
入力寿命はtarget_timeout_secパラメーター、既定300msとして認識側と合わせる。
画像内の点の追跡は認識側、左右方向・近さ・速度・操舵の判断は本ノードで行う。

## データと制御

- 入力：`/vision/ground_target`（std_msgs/String JSON）。`tracking` かつ `target_valid=true` の `target.target_normalized.x/y`（0〜1）を使用。
- 出力：セッション名前空間の `autonomous/command`（std_msgs/String JSON）。速度、操舵、緊急停止要求、判断理由、相対距離、左右偏差を20 Hzで発行。
- 左右偏差：`2*x-1`。中央±0.1は直進。画像右なら右旋回、画像左なら左旋回。既存のsteer制御を使い、後輪Duty維持・前輪±60%補正（自動走行）を適用。
- 水平線：`horizon_y` パラメーター、初期値0.5（0以上0.75未満）。相対距離 `d=(0.75-y)/(0.75-horizon_y)`。
- 速度目標：`0.10+0.10*d` m/s。水平線位置で0.20、停止境界の手前で約0.10。未校正のため実速度の保証値ではなくモーター制御への指令値。
- `y>=0.75` は前進停止（速度0、左右座標に応じたその場旋回、reason=`target_near_stop`）。有効状態を維持し、新しい有効目標が `horizon_y<=y<0.75` に戻れば自動再開する。緊急停止要求は発行しない。
- 一時的な未検出は後述の予測を最大1秒使用する。不正座標、水平線より上、認識異常、画像の寿命300ms超過では速度・操舵を0にする。通常の目標消失停止は新しい有効目標で再開する。
- source_frame.stampで画像自体の古さを確認する。同じ画像の再配信では寿命を延長しない。タイマーと受信後の寿命判定には単調時計を使用。

距離は画像上の相対値（水平線側1、停止境界0）。m単位の距離ではない。実距離にはカメラの高さ・姿勢・内部パラメーターの校正が必要。

## 指令元の選択と停止

`pc_bridge` が専用モーターノードと専用自動走行ノードを起動し、モーターへの指令を一本化する。
初期指令元はmanual。PC画面の「PC手動」「自動走行」で選択する。
切替は停止・無効化を伴い、改めて「有効化」が必要。自動モードでは方向ボタン・一輪操作を無視。
PCの「停止 / 無効化」、Space、Esc、フォーカス喪失、接続切断は自動走行中も有効。
PCからのheartbeatが350 ms途絶すると無効化。自動指令が350 ms途絶した場合や自動ノード終了時も無効化する。
ブリッジ停止時はモーター側500 msのwatchdogが停止させる。

SSH JSON操作に `{"op":"source","value":"manual|auto","id":番号}` を追加。
statusに `command_source` と `autonomous` を追加する。
自動ノードの出力は候補指令であり、モーターへ直接送らない。PCブリッジを通さず起動しただけでは走行しない。

## 起動

Piの作業コピーでビルドする：

```bash
cd ~/ros2-rove-one/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select pi4_motor_control pi4_camera_vision
source install/setup.bash
```

認識ノードは従来の `camera_vision.launch.py` で起動。PC映像表示の起動経路でも認識を起動する。
PCでSSH接続→「自動走行」→「有効化」。初期設定はdry-run。
モーターと認識は同じROS_DOMAIN_ID（既存PC設定では88）を使用する。
`autonomous_driving` は `/vision/ground_target` を購読するため、認識を別名前空間で起動する場合はROS remapが必要。

## Pi上の統合試験

ビルド後、実車モーターに出力しない専用セッションで実行する：

```bash
cd ~/ros2-rove-one/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ROS_DOMAIN_ID=89 python3 src/pi4_motor_control/scripts/validate_autonomous.py
```

合成ライト画像を実際のBrightGroundDetectorへ渡し、ROSで自動ノード・PCブリッジ・dry-runモーターへ接続する。
既存カメラのdomain 88とは分離する。左右操舵、近接減速、Unknown、画像停止、PC停止、手動／自動切替、PC heartbeat途絶、下1/4での通常停止・自動再開と、PC緊急停止からの再有効化を確認する。
`pc_bridge.py --target-topic /任意の目標トピック` で購読先を変更できる。通常は従来の `/vision/ground_target`。

## 停止と緊急停止の要件（2026-11-10改訂）

|停止の種類|発生条件|停止時|復帰条件|
|---|---|---|---|
|近接による前進停止|画面下1/4（y>=0.75）に有効な実測目標|前進0、左右追従のその場旋回。有効状態を維持|中央なら旋回0。走行範囲へ戻れば前進再開|
|通常停止|水平線より上、予測期限切れ、目標不正、画像期限切れ|速度・操舵0。有効状態を維持|有効な目標で再開|
|停止・無効化|PCの停止/Space、フォーカス喪失、通信途絶、自動ノード終了、指令元切替|全輪出力0、無効化|接続・指令の正常性が回復したうえで明示的に有効化|
|緊急停止|PCの緊急停止ボタン、Esc、emergency_stop=trueの明示要求|全輪出力0、無効化、緊急停止フラグを保持|「有効化」1回で緊急停止フラグを解除して有効化。通常の走行指令・目標再検出だけでは解除しない|

- 有効化時は古い走行指令を破棄する。手動は操作を解放した新しい指令を待ち、自動は新しい有効な目標に基づく指令で再開する。
- PCブリッジでは従来どおり新鮮なゼロheartbeatと手動操作解放を有効化の前提とする。有効化しても目標が下1/4、または有効な実測・予測がなければ通常停止を継続する。
- 従来の「緊急停止ラッチ解除」操作（emergency_stop=false）は残し、解除だけでは有効化しない。再開は「有効化」でも行える。
- 緊急停止が再度要求された場合は再び停止する。通信回復や目標移動による緊急停止の自動解除はしない。
- 現在の実装対象はソフトウェアの停止。独立した物理非常停止スイッチや障害物検知に連動する緊急停止は未実装。

## 高速追従と一時未検出の予測（2026-11-10）

- 撮影・認識の目標fpsを10から20へ変更。カメラの320×240 MJPEGは実機問い合わせで20fps対応を確認。light_spot用設定も20fpsにそろえる。
- 自動走行の座標判断とブリッジからモーターへの指令は20Hz。最新フレーム優先と追跡確定2フレームは維持する。
- prediction_timeout_sec=1.0（0〜1、0で無効）。lost/searchingのno_candidate・confirming_candidateのみ、一時未検出として予測可能。
- 同じtrack_idの直近2回の実測から画像内速度を算出し、等速直線で予測する。1回しか実測がなければ位置保持。track_idが変わった場合と実測間隔が300msを超えた場合は速度履歴をリセット。
- 予測の期限は最後の実測画像の時刻から最大1秒。未検出の繰り返しや予測出力で期限を延長しない。1秒に到達したら停止。
- 予測中は最後の実測時より加速しない。予測点が画面外・水平線より上・下1/4へ入ったら停止。停止範囲内だった実測から予測だけで走行再開しない。
- 画像自体や認識結果の配信が300ms途絶した場合、複数候補で曖昧な場合、不正データ・認識エラーの場合は予測せず停止。緊急停止・PC無効化・通信途絶は予測より優先する。
- 予測中の指令はreason=predicting、prediction_age_sec、predicted_target_normalizedを含む。再検出した実測を最優先し、通常追従へ戻る。

実機検証：20fps設定で撮影15.02fps・認識15.02fps、平均認識処理20.53msを観測。設定値と実効fpsは一致を保証しない。単体・ROS契約68件と、予測継続・1秒期限停止を含むdry-run統合試験が合格。

## 最低速度・旋回力・前進停止中の追従（2026-11-10）

- 「初速0.05」は走行時の最低速度指令0.05m/sとして適用。速度式は0.05+0.15*d、最大0.20m/s。停止時は0m/s。
- 自動走行中の旋回ゲインを2倍。従来の操舵入力は正負だけで走行中の補正を決めていたため、入力値だけを2倍にする方法は使用しない。
- 自動指令をmode=auto_steerとしてモーターへ渡す。走行中の前輪補正は±60%（外側160%・内側40%）、後輪は維持。その場旋回は従来の前輪の左右逆転出力とし、後輪は0。最大Dutyで制限する。
- 手動mode=steerは従来の±30%を維持。これは操舵出力の増加であり、機械的な旋回角度の実測2倍を保証する値ではない。
- y>=0.75でも有効な実測目標が左右にある場合は、その場旋回する。中央不感帯（abs(2*x-1)<0.1）では旋回0。
- 前進停止中に目標が見えなくなった場合、古い近接座標で旋回は続けない。PC停止/無効化・緊急停止は全輪停止を維持。

2026-11-11改訂：停止中のその場旋回はゲイン2を適用せず、従来のゆっくりした出力とする。自動走行中は±60%、PC手動走行中は±30%を維持。停止中は両モードとも従来出力。

2026-11-11再改訂：停止中の旋回出力は手動・自動とも、直前の従来出力からさらに半分（前輪Duty=±0.5*duty(turn)、後輪0）にする。走行中の自動±60%・手動±30%は維持。

2026-11-11最新改訂：停止中の旋回は手動・自動とも半減を取り消し、従来Duty（±duty(turn)）へ戻す。自動走行の最低速度は0.10m/s、最大0.20m/s、式は0.10+0.10*d。走行中の自動±60%・手動±30%は維持。
